# 上架 Chrome 应用商店

## 两个版本怎么安排

建议**只维护一份代码**，发两个渠道：

| 渠道 | 给谁 | 怎么装 |
| --- | --- | --- |
| GitHub 仓库 | 想自己看代码、不信任商店自动更新的人 | 下载源码 →`chrome://extensions`→ 打开开发者模式 →「加载已解压的扩展程序」 |
| Chrome 应用商店 | 普通用户，搜到就装，免费，自动更新 | 商店页面点「添加至 Chrome」 |

两边是同一份代码，商店版同样不联网。这样商店页面可以写「开源、可核对」，也不用同时修两套。
以后如果商店版要加联网功能（比如云同步），再从这份代码分出去，并改隐私政策。

## 两个分支

| 分支 | 用途 |
| --- | --- |
| `main` | 开源版。所有本地功能（填表、资料、侧边栏、投递记录）都在这里开发，不联网 |
| `store` | 应用商店版 = `main` + 只在商店版里的功能（比如搜索岗位，需要联网） |

规则：两边都要的功能只在 `main` 上改，然后在 `store` 上合并 `main`：

```bash
git switch store && git merge main
```

商店版加了联网功能后，`store` 上的 `PRIVACY.md` 和 `manifest.json` 里的 `connect-src` 要跟着改，写清楚连哪些网站、传什么。上传商店的 zip 在 `store` 分支上打包。

## 商店版已经准备好的东西（store 分支）

- 填写商店后台要用的全部文字（说明、权限理由、数据使用勾选项）：`store/listing.md`
- 5 张截图（1280×800）和小宣传图（440×280）：`store/*.png`，用虚构数据生成，重新生成：`sh store/make.sh`
- 岗位数据不打包进扩展，见 `scripts/jobs/README.md`。上线前要做：
  1. 把仓库设为公开（`raw.githubusercontent.com` 只能读公开仓库）
  2. 推送 `store` 分支；GitHub 的定时任务只认默认分支上的 workflow，所以要么把默认分支改成 `store`，要么把 `.github/workflows/jobs-data.yml` 也放到默认分支
  3. 在仓库的 Actions 页面手动运行一次「岗位数据」，确认 `jobs-data` 分支生成、`https://raw.githubusercontent.com/HideInSky/resume-autofill/jobs-data/index.json` 能打开
  4. 以后加国内镜像：在 `src/jobs-config.js` 加地址，同时把同一个地址加进 `manifest.json` CSP 的 `connect-src`

## 上架前要准备的

1. **开发者账号**：用 Google 账号在 <https://chrome.google.com/webstore/devconsole> 注册，一次性付 5 美元，账号要开两步验证。
2. **公开的隐私政策网址**：扩展处理个人信息，商店要求必须有。把仓库推到 GitHub 后用 `PRIVACY.md` 的网址即可。
3. **安装包**：运行 `sh scripts/pack.sh`，得到 `resume-autofill-<版本号>.zip`。
4. **商店素材**
   - 图标 128×128：`icons/icon128.png`（已有）
   - 截图至少 1 张，1280×800 或 640×400：建议 3 张——侧边栏填写清单、资料页、填好的表单（用虚构资料）
   - 小宣传图 440×280（必填）
   - 名称不超过 75 字符、简短说明不超过 132 字符、详细说明
   - 名称和图标不要用别家的商标（Simplify、OfferLink 等），会被拒或被投诉下架

## 提交步骤

1. 开发者后台 →「新建项目」→ 上传 zip。
2. **商品详情**：填说明、类别选「工作流程和规划」或「工具」、语言选中文（简体），上传截图和宣传图。
3. **隐私权规范**（最容易被打回的一页）：
   - 单一用途：`自动填写求职申请表单并上传简历`
   - 逐个说明权限用途：
     - `storage` / `unlimitedStorage`：在本机保存用户资料和简历文件
     - `activeTab` / `scripting`：用户点击后，把资料填进当前网页的表单
     - `sidePanel`：在侧边栏显示填写结果和可复制的资料
     - 主机权限（可选的 `<all_urls>`）：用户打开「自动填写」后，在其打开的网申页面上填表；招聘网站数量太多，无法逐个列出
   - 是否使用远程代码：否
   - 数据使用：勾选「个人身份信息」「身份验证信息」（保存网申账号密码），并勾选三项承诺（不出售、不用于无关用途、不用于信贷判断）
   - 填隐私政策网址
4. **分发**：免费、公开、选择地区（全部地区即可）。
5. 提交审核。申请了访问所有网站的权限，会进入人工深入审核，通常几天，偶尔两三周。被打回时邮件里会写原因，改完重新提交。

## 以后更新

改 `manifest.json` 里的 `version`（必须比上一次大）→ `sh scripts/pack.sh` → 后台「上传新版本」→ 提交审核。
